# Threat model

Primary assets are authorization scope, tenant data, provider credentials, raw evidence, reports, audit history, AI prompts/outputs, and budgets. Trust boundaries exist at the browser/API, OIDC issuer, worker queues, providers/public internet, object store, premium AI services, and webhook receivers.

Key threats and controls: cross-tenant IDOR (claim-derived context, RLS, ownership joins); SSRF/DNS rebinding (resolution checks at connect time, egress proxy, redirect revalidation); scope confusion (typed allow/deny rules and active attestation); query injection (provider-native builders, schemas, no shell/browser interpolation); secret leakage (vault references, redaction, local routing); poisoned imports/results (quarantine, provenance, deterministic normalization); duplicate amplification (canonical hashes with preserved provenance); AI prompt injection/output fabrication (evidence delimiters, strict output schema, deterministic facts, human review); queue replay (idempotency and tenant quotas); webhook forgery (HMAC/timestamp/replay cache); evidence tampering (content hashes, encryption, immutable audit); audit deletion (append-only grants and external export).
